# Debugging and Verification

You need to perform functional verification testing based on the following test cases.

| Test Case | Prerequisite | Step | Expected Result |
| --- | --- | --- | --- |
| Obtaining the API level of the server | • The industry app has obtained the access permission. • The industry app has integrated the Health Industry SDK. • The industry app has been installed on the mobile device. | • Call the API for obtaining the API level of the server. | For step 1, the API level of the server is obtained successfully, and result code **0** is returned. |
| Managing the connection status between your app and the server | • Call the API for registering the connection status between the industry app and the server. • Call the API for unregistering the connection status between the industry app and the server. | For step 1, the connection status between the industry app and the server is registered successfully, and result code **0** is returned. For step 2, the connection status between the industry app and the server is unregistered successfully, and result code **0** is returned. |  |
| Certificate path management | • Call the API for setting the certificate path. • Call the API for querying the certificate path. • Call the API for deleting the certificate path. | For step 1, the certificate path is set successfully, and result code **0** is returned. For step 2, the certificate path is queried successfully, and the returned certificate path is consistent with that set in step 1. For step 3, the certificate path is deleted successfully, and result code **0** is returned. |  |
| Device connection management | • The industry app has obtained the access permission and preconfigured the required certificate. • The industry app has integrated the Health Industry SDK. • The industry app has been installed on the mobile device. | • Call the API for registering a listener for the industry wearable connection status. • Call the API for scanning for industry wearables. • Call the API for pairing with an industry wearable. • Call the API for obtaining the paired industry wearable. • Call the API for disconnecting from the industry wearable. • Call the API for reconnecting to the industry wearable. • Call the API for deleting the industry wearable. • Call the API for obtaining the paired industry wearable. | For step 2, the industry wearables that can be connected are detected. For step 3, the industry app is successfully connected to the industry wearable. Status code **1** and then **2** are returned. For step 4, the paired industry wearable is obtained and information about the wearable is returned. For step 5, the industry wearable is successfully disconnected, and status code **3** is returned. For step 6, the industry app is successfully reconnected to the industry wearable. Status code **1** and then **2** are returned. For step 7, the industry wearable is successfully deleted, and status code **3** is returned. For step 8, no paired industry wearable is obtained. |
| Device information and status | • The industry app has obtained the access permission and preconfigured the required certificate. • The industry app has integrated the Health Industry SDK. • The industry app has been installed on the mobile device. • The industry wearable has been connected to the mobile device through the industry app. | Taking setting and querying basic user information as an example: • Call the API for setting basic user information. • Call the API for querying basic user information. | For step 1, the basic user information is set successfully, and result code **0** is returned. For step 2, the basic user information is queried successfully, and the basic user information returned is consistent with what you have set in step 1. |
| Health data | Taking body temperature query as an example: • Wear an industry wearable. • Measure body temperature on the industry wearable. • Call the API for querying body temperature data. | For step 3, the body temperature data is queried and returned successfully. |  |
| Workout data | Taking single workout data query as an example: • Wear an industry wearable. • Start an outdoor running workout on the industry wearable, and end it 10 minutes later. • Call the API for querying the single workout record. | For step 3, the single workout record is queried and returned successfully. |  |
| Daily activity data | Taking daily activity data query as an example: • Wear an industry wearable. • Start an outdoor walk workout on the wearable and walk. • Call the API for querying daily activity data. | For step 3, the daily activity data is queried and returned successfully. |  |
| Sensor data | Taking real-time photoplethysmography data subscription as an example: • Wear an industry wearable. • Call the API for subscribing to real-time PPG data. | For step 2, the real-time PPG data is subscribed to successfully, and result code **0** is returned. |  |
| Device event management | Taking SOS event subscription as an example: • Call the API for subscribing to SOS events. • Press the power button on the wearable for five consecutive times. | For step 1, SOS events are subscribed to successfully, and status code **0** is returned. For step 2, an SOS event is reported, and result code **10** is returned. |  |
| App control | Taking starting SpO2 measurement as an example: • Wear an industry wearable. • Call the API for starting SpO2 measurement. | For step 2, SpO2 measurement is started successfully, and result code **0** is returned. |  |
| Enhanced device capabilities | Taking favorite contacts as an example: • Call the API for setting favorite contacts. • Call the API for querying favorite contacts. | For step 1, favorite contacts are set successfully, and result code **0** is returned. For step 2, favorite contacts are queried successfully, and the returned favorite contacts are consistent with those set in step 1. |  |
| Communication with wearable apps | Taking template-based notifications on wearables as an example: • Call the API for sending a template-based notification to an industry wearable. • Check whether the notification received by the industry wearable is consistent with that sent by the industry app. | For step 1, the template-based notification is sent successfully, and status code **0** is returned. For step 2, the notification received by the wearable is consistent with that sent by the industry app. |  |
| Log management | • Call the API for setting the log switch. • Call the API for querying the log switch state. | For step 1, the log switch is set successfully, and result code **0** is returned. For step 2, the log switch state is queried successfully, and the returned status is consistent with that set in step 1. |  |
| Restoring a wearable to factory settings | • Call the API for restoring a wearable to its factory settings. | For step 1, the wearable is restored to its factory settings successfully, and result code **0** is returned. |  |
