# Authentication and Authorization Example

This section describes how an app can use a client ID to access a HUAWEI ID and generate an access token, which is mandatory for calling APIs to access resources authorized by the user. To do so, you must ensure that:

- You have a HUAWEI ID.
- You have enabled Health Kit.
- You have applied for the required data permissions on HUAWEI Developers, and the application has been approved.

#### Acronyms and Abbreviations

| Acronym/Abbreviation | Full Name |
| --- | --- |
| code | authorization code |
| AT | access token |
| RT | refresh token |

An app is authorized using the authorization code based on OAuth 2.0, when accessing Health Kit. For details, see [Example of Using the Authorization Code](#EN-US_TOPIC_0000001054581058__section9339449355).

- Generate an authorization code.
- Generate an access token based on the authorization code.
- After the access token expires, use the refresh token to obtain a new access token.

#### Example of Using the Authorization Code

- Generate an authorization code. The code is obtained by redirecting the user's browser (or the browser component in the mobile phone or desktop app) to the address https://oauth-login.cloud.huawei.com/oauth2/v3/authorize. If an error occurs, see [Errors and Troubleshooting](https://developer.huawei.com/consumer/en/doc/HMSCore-Guides-V5/open-platform-error-0000001053869182-V5). The following table lists the required parameters. 
| Parameter Name | Mandatory (M)/Optional (O) | Description |
| --- | --- | --- |
| client_id | M | App ID obtained when the app is registered. |
| response_type | M | The value is always **code**. |
| redirect_uri | M | URI to be called back after the authorization, that is, the URI for receiving the authorization code. If a user revokes authorization, the URI is called back and appended with error=access_denied. The value of **redirect_uri** must be the same as the value of **Redirect_URI** set when registering the app. The value must be encoded using URLEncode. |
| scope | M | Character string array separated by spaces. The spaces will be changed to plus signs (+) after URL encoding. The character string openid must be contained. For other information, see [Health Kit Scope List](https://developer.huawei.com/consumer/en/doc/development/HMSCore-Guides-V5/scope-list-0000001055419280-V5#EN-US_TOPIC_0000001055419280__section1078716412914). |
| state | O | State reflected back in the URI that is called back when a user's browser is redirected to **redirect_uri**. This parameter should match the regular expression **^[0-9a-zA-Z:/\.]+$**, and is advised to contain up to 200 characters. According to the OAuth 2.0 protocol, you are advised to use the **state** parameter to prevent CSRF attacks. |
| display | O | Authorization page display style. The default value is **page**. The value is **touch for the mobile app**, and **page** for the web app. |
| access_type | O | When the parameter is set to **offline**, a refresh token will be returned together with the access token in the second step. |
 For example, when an app whose **client_id** is **101489619** needs to request the access permission of the height and weight data (https://www.huawei.com/healthkit/heightweight.read) and calorie data (https://www.huawei.com/healthkit/calories.read) of a user and then redirect to https://www.example.com after authorization, if the user login and authorization screen needs to be displayed in the pop-up window, the app needs to redirect the user's browser to the following URL: 
```cpp
https://oauth-login.cloud.huawei.com/oauth2/v3/authorize?response_type=code&state=state_parameter_passthrough_value&client_id=101489619&redirect_uri=http%3A%2F%2Fwww.example.com&scope=openid+https%3A%2F%2Fwww.huawei.com%2Fhealthkit%2Fheightweight.read+https%3A%2F%2Fwww.huawei.com%2Fhealthkit%2Fcalories.read&access_type=offline&display=touch
```

After the user agrees to authorize access, the authorization server redirects the user's browser to **redirect_uri** with the parameters **code** and **state** (if contained in the request for obtaining the access token). - Use the authorization code to obtain the access token. After obtaining the authorization code in the previous step, it can be used to generate an access token, by sending a request using the POST method from the app's server to the Huawei OAuth 2.0 authorization service address https://oauth-login.cloud.huawei.com/oauth2/v3/token with the following input parameters: 
| Parameter Name | Mandatory (M)/Optional (O) | Description |
| --- | --- | --- |
| grant_type | M | The value is always **authorization_code**. |
| code | M | Authorization code obtained in the first step. The code expires in five minutes and can be used only once. |
| client_id | M | App ID. |
| client_secret | M | Secret key of the app, which can be viewed on HUAWEI Developers. |
| redirect_uri | M | The value must be the same as the value of **redirect_uri** passed to obtain the authorization code. The value must be encoded using URLEncode. |
 **Request example** 
```cpp
POST /oauth2/v3/token HTTP/1.1
Host: oauth-login.cloud.huawei.com
Content-Type: application/x-www-form-urlencoded
grant_type=authorization_code&code=DQB6e3x9LAmTy2FrNSkgsWZxnzDsU75X9I93%2Fo7S2GrErASX0nXSEVyGJAduOqH%2FRqmME9NSMYELXdIJz4YiYvI9w0hVbES7EfeEx2sepUBceh4%2FbUI1YXkawMUZle1o2NkirHK6aGOt%2FCRZxfGxu5DCqCRONnoAzMBWsXT6Hk0YnysyTZ1SEu5umDhKvWT%2Bb5Fp2XoLtRr1mPlYmMvIKNnwc8PDv4B8RHRryIvGLCO%2Bp2d%2BTMTnLwySoOX6sZ3XaQ0fGgZpymwhHAAMZEI74IFB%2FeGWlyvuPwa2MjRwF9%2FpzeVyjqg9gvwZ%2FVotYZzQiXbFBsEs%2B3DTXg%3D%3D&client_id=101489619&client_secret=0rDdfgyhytRtznPQSzr5pVw2&redirect_uri=http%3A%2F%2Fwww.example.com
```

| expires_in | M | Validity period of the access token (unit: second). |
| scope | M | Scope contained in the access token generated. |

- Obtain the access token through refresh token. A refresh token can be used to obtain a new access token by sending a request using the POST method from the app's server to the Huawei OAuth 2.0 authorization service address https://oauth-login.cloud.huawei.com/oauth2/v3/token with the following input parameters: 
| Parameter Name | Mandatory (M)/Optional (O) | Description |
| --- | --- | --- |
| grant_type | M | The value is always **refresh_token**. |
| refresh_token | M | Refresh token for the access token. |
| client_id | M | App ID. |
| client_secret | M | Secret key of the app, which can be viewed on HUAWEI Developers. |
| access_type | O | This parameter is restricted. To use this parameter, you must apply for it in advance. It can be used to refresh the refresh_token. If this parameter is set to **offline**, a new refresh token is returned together with the access token. You are advised to check whether the new refresh token is the same as the current refresh token. If not, use the new refresh token. CAUTION: Ensure that the new refresh token has a value and is different from the current refresh token. |
 **Request example** 
```cpp
POST /oauth2/v3/token HTTP/1.1
Host: oauth-login.cloud.huawei.com
Content-Type: application/x-www-form-urlencoded
grant_type=refresh_token&client_id=101489619&client_secret=0rDdfgyhytRtznPQSzr5pVw2&refresh_token=CgB6e3x9eIW+2aYelXZuZ361MviOwbbBTzFWglSTPwTzWY8MpWydocoU8bYxM253JQABPrR98G1z6hIT6QsoknGpND1eeJgvXfQzEJJJtRQvqFs9N6rmXSJMHOrRta3iXU1i9abcdygqtwgGOi017x5oITcYHAOx1lV4nDF0gqleySVtbg==
```

| Parameter Name | Description |

| refresh_token | Refresh token used to refresh the access token. You can compare the value with the **refresh_token** in the request. If they are different, it is recommended that you save this value to ensure the validity of the **refresh_token** (to avoid RT expiration). |

#### Open Capability APIs

You can use the **huawei.oauth2.user.getTokenInfo** API to query information carried by tokens such as **openid**, **clientId**, and scopes of a user (check whether the generated access token meets the expectation).

```cpp
POST https://oauth-api.cloud.huawei.com/rest.php?nsp_fmt=JSON&nsp_svc=huawei.oauth2.user.getTokenInfo
```

API description: This API is used to query a user's token information, such as **open_id**. This API is a basic capability API and is not provided by the cloud platform. The **req** parameter is optional for this API.

Direction: third-party system -> cloud platform

HTTPS request method: POST

Parameters of request head message

| Parameter Name | Type | Mandatory (M)/Optional (O) | Description |
| --- | --- | --- | --- |
| nsp_svc | String | M | The value is always **huawei.oauth2.user.getTokenInfo**. |
| nsp_fmt | String | M | The value is always **JSON**. |

Request body

| Parameter Name | Type | Mandatory (M)/Optional (O) | Description |
| --- | --- | --- | --- |
| open_id | String | M | The value is always **OPENID**. The API returns the open ID only when this parameter is transferred in the request. |
| access_token | String | M | Access token. |

Response body

| Parameter Name | Type | Mandatory (M)/Optional (O) | Description |
| --- | --- | --- | --- |
| union_id | String | O | This field can be returned only after the permission is granted on Huawei Developers. |
| scope | String | M | List of the scope authorized by the user. |
| open_id | String | O | OpenId (globally unique based on user information). |
| expire_in | int | M | Expiration time of the access token (unit: second). |
| client_id | String | M | App ID. |
