# Commissioning and Verification

Use the [test tool](https://developer.huawei.com/consumer/en/doc/development/health-Library/31206) to perform the tests against the following test cases.

| Test Case | Prerequisites | Procedure | Expected Results |
| --- | --- | --- | --- |
| To verify authorization for data sharing. | • You have applied for the required fitness or health data permissions on HUAWEI Developers and the application has been approved. • Your app, the HUAWEI Health app, and HMS Core (APK) have been installed on the phone. • Your app has been developed as instructed to request read and write permission on data types through the HUAWEI ID API. | Open your app to call account authorization. | The authorization screen is displayed, showing all items for which your app requires permissions. By default, no permission is granted for any item. Turn on the switch to authorize data sharing. |
| To verify that the third-party app can read data opened by the HUAWEI Health app. | • You have applied for the required fitness or health data permissions on HUAWEI Developers and the application has been approved. • Your app, the HUAWEI Health app, and HMS Core (APK) have been installed on the phone. • The data sharing authorization has been granted. • There is fitness and health data in the HUAWEI Health app. • Your app calls the query API by following the app development guide. | The third-party app calls the execQuery method to query authorized data. For example, the step count (HiHealthPointType.DATA_POINT_STEP_SUM) of the current day is to be queried. | The API is called successfully. The result code is 0, and the step count of the current day is returned. The step count is the same as that displayed on the home screen of the HUAWEI Health app. |
| To verify that the third-party app can read the real-time workout data. | • You have applied for the required fitness or health data permissions on HUAWEI Developers and the application has been approved. • Your app, the HUAWEI Health app, and HMS Core (APK) have been installed on the phone. • The data sharing authorization has been granted. • The HUAWEI Health app has obtained the storage and location permissions from the user. • Your app calls the workout start and end APIs by following the app development guide. | • Your app calls the registerSportData method to start obtaining the real-time workout data. • Your app calls the startSport method and passes the corresponding sportType, for example, HiHealthKitConstant.SPORT_TYPE_RUN, to start outdoor running. • Your app calls the stopSport API to stop the workout. • Your app calls the unregisterSportData API to stop obtaining the real-time workout data. | • The API is successfully called. The result code is 0, and the registration for obtaining real-time workout data starts. • The API is successfully called. The result code is 0, and the workout information is displayed in the notification bar of the phone, indicating that the workout is going on. After the workout is started, the real-time workout dataset Bundle can be returned. • The API is successfully called. The result code is 0, the workout ends, and real-time workout data stops being returned. • The API is successfully called. The result code is 0, and the method for obtaining real-time workout data is deregistered. |
| To verify that the third-party app can read the real-time heart rate data. | • You have applied for the required fitness or health data permissions on HUAWEI Developers and the application has been approved. • Your app, the HUAWEI Health app, and HMS Core (APK) have been installed on the phone. • The data sharing authorization has been granted. • A wearable device that supports heart rate monitoring has been paired with the phone using the HUAWEI Health app and is connected. • Your app calls the API for obtaining the real-time heart rate data by following the app development guide. | • The third-party app calls the startReadingHeartRate method to start obtaining the real-time heart rate data. • Your app calls the stopReadingHeartRate method to stop obtaining the real-time workout data. | • The API is successfully called, and the result code is 0. The real-time heart rate data is successfully obtained. The following data is returned at a fixed interval:{"hri_info":0,"hr_info":69,"hrsqi_info":0,"time_info":1591361991000} • The API is successfully called. The result code is 0, and real-time heart rate data stops being returned. |
| To verify that the third-party app can write data to the HUAWEI Health app. | • You have applied for the required fitness or health data permissions on HUAWEI Developers and the application has been approved. • Your app, the HUAWEI Health app, and HMS Core (APK) have been installed on the phone. • The data sharing authorization has been granted. • Your app calls the data storage API by following the app development guide. | Your app calls the saveSample method to store data. For example, the weight data (HiHealthSetType.DATA_SET_WEIGHT_EX) is to be stored. | The API is successfully called, and the result code is 0. [true,true] is also returned, indicating that the data is successfully stored. The weight value displayed on the weight card on the home screen of the HUAWEI Health app or on the secondary-level screen is the same as the written data. |
| To verify the data sharing permission can be manually canceled. | • You have applied for the required fitness or health data permissions on HUAWEI Developers and the application has been approved. • Your app, the HUAWEI Health app, and HMS Core (APK) have been installed on the phone. • The data sharing authorization has been granted. • There is fitness and health data in the HUAWEI Health app. • Your app calls the query API by following the app development guide. | • Open the HUAWEI Health app, go to **Me** > **Privacy management** > **Data sharing and authorization** > **AUTHORIZED VIA ACCOUT**, and touch your app to access the authorization screen. Then turn off the related switches for allowing data reading. • Your app calls the data query API to read the data for which the share switch has just been turned off. | • After the switch is turned off, data sharing authorization is disabled. • Data cannot be read. Error code 1001 is returned. |
