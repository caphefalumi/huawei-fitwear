# Debugging and Verification

Perform the system test on functions according to the test cases.

| Test Case | Prerequisite | Step | Expected Result |
| --- | --- | --- | --- |
| Your app launches the user authorization screen. | • The Huawei Health app has been installed on the phone and the app has been logged in to a HUAWEI ID. • The Wear Engine SDK has been integrated on your app. • Your app has been installed on the phone. | • Open your phone app and call the user authorization API. • On the user authorization screen, turn on the corresponding switches. • Confirm the authorization on the bottom of the screen. • Call the API in Step 3 for granting the permissions. | • In Step 2, the user authorization screen is displayed. • In Step 4, no "User unauthorized in wear engine" error information is returned when the API is called. |
| The user cancels the authorization for your app. | • The Huawei Health app has been installed on the phone and the app has been logged in to a HUAWEI ID. • The Wear Engine SDK has been integrated on your app. • Your app has been installed on the phone. • Permissions for your app have been granted. | • Open the Huawei Health app and touch **Me**. • Go to **Settings** > **Open device capability**. Touch the app requiring the authorization cancellation. • On the user authorization screen, turn off the corresponding switches. • Call the API in Step 3 for canceling the granted permissions. | • In Step 2, the user authorization screen is displayed. • In Step 3, the corresponding user permissions have been disabled. • In Step 4, "User unauthorized in wear engine" error information is returned when the API is called. |
| Obtain the information about the paired wearable device. | • The Huawei Health app has been installed on the phone and the app has been logged in to a HUAWEI ID. • The Wear Engine SDK has been integrated on your app. • Your app has been installed on the phone. • Your app has been installed on the wearable device. • The wearable device has been paired with and connected to the Huawei Health app. • Permissions for your app have been granted by the user. | Your phone app calls the API for pairing devices. | The API has been called and the Querying Wearable Device Information has been returned. |
| The phone uses the **ping** method to check whether the wearable device is reachable. | Your phone app calls the **ping** method to check whether the wearable device is reachable. | The API is successfully called, your wearable app can respond to the **ping** method, and the return code is **202**. |  |
| The wearable device uses the **ping** method to check whether the phone is reachable. | Your wearable app calls the API for checking whether the phone is reachable. | The API is successfully called, your phone app can respond to the **ping** method, and the return code is **205**. |  |
| The phone sends messages to the wearable device. | • Your wearable app calls the API for receiving registry messages. • Your phone app calls the API for sending messages to the wearable app. • Check that the message received by your wearable app is consistent with that sent by the phone app. • Your wearable app calls the API for canceling the reception of registry messages. • Your phone app calls the API for sending messages to the wearable device. • Check whether the wearable device has received the message. | • In Step 2, your phone app successfully sends the message, the sending progress is displayed as **100**, and the return code is **207**. • In Step 3, check that the message received by your wearable app is consistent with that sent by the phone app. • In Step 5, your phone app fails to send the message, the sending progress is displayed as **0**, and the return code is **206**. • In Step 6, your wearable app cannot receive the message. |  |
| The phone sends files to the wearable device. | • Your wearable app calls the API for receiving registry messages. • Your phone app calls the API for sending files to your wearable app. • Check that the file received by your wearable app is consistent with that sent by the phone app. • Your wearable app calls the API for canceling the reception of registry messages. • Your phone app calls the API for sending files to the wearable device. • Check whether the wearable device has received the file. | • In Step 2, your phone app successfully sends the file, the sending progress is displayed as **100**, and the return code is **207**. • In Step 3, check that the file received by your wearable app is consistent with that sent by the phone app. (Demo on the wearable device is used.) • In Step 5, your phone app fails to send the file, and the result code starting with "199" is returned. • In Step 6, your wearable app cannot receive the message. |  |
| The wearable device sends messages to the phone. | • Your phone app calls the API for receiving registry messages. • Your wearable app calls the API for sending messages to the phone app. • Check that the message received by your phone app is consistent with that sent by the wearable app. • Your phone app calls the API for canceling the reception of registry messages. • Your wearable app calls the API for sending messages to the phone app. • Check whether the phone has received the message. | • In Step 2, your wearable app successfully sends the message, the sending progress is displayed as **100**, and the return code is **207**. • In Step 3, check that the message received by your phone app is consistent with that sent by the wearable app. • In Step 5, your wearable app fails to send the message, the sending progress is displayed as **0**, and the return code is **206**. • In Step 6, your phone app cannot receive the message. |  |
| The wearable device sends files to the phone. | • Your phone app calls the API for receiving registry messages. • Your wearable app calls the API for sending files to the phone app. • Check that the file received by your phone app is consistent with that sent by the wearable app. • Your phone app calls the API for canceling the reception of registry messages. • Your wearable app calls the API for sending files to the phone app. • Check whether your phone can receive files. | • In Step 2, your wearable app successfully sends the file, the sending progress is displayed as **100**, and the return code is **207**. • In Step 3, check that the file received by your phone app is consistent with that sent by the wearable app. (Demo on the phone is used.) • In Step 5, your wearable app fails to send the file, and the result code starting with "199" is returned. • In Step 6, your phone app cannot receive the message. |  |
| Query the status of the wearable device. | Querying the battery level and wearing status is used as an example: • Your phone app calls the API for querying the battery level of the wearable device. • Wear the wearable device. • Your phone app calls the API for querying the wearing status of the wearable device. • Remove the wearable device from the wrist. • Your phone app calls the API for querying the wearing status of the wearable device. | • In Step 1, the battery level of the wearable device can be queried. • In step 3, the device status queried by your app is that the wearable device is worn. • In step 5, the device status queried by your app is that the wearable device is not worn. |  |
| Subscribe to the wearable device status. | Subscribing to the connection status and wearing status is used as an example: • Your phone app calls the API for subscribing to the wearing status of the wearable device. • Keep your phone away from the wearable device until the phone is disconnected from the wearable device. • Reconnect the phone to the wearable device. • Your phone app calls the API for subscribing to the wearing status of the wearable device. • Wear the wearable device. • Remove the wearable device from the wrist. | • In Step 2, the third-party phone app will receive a wearable device disconnection event. • In Step 3, the third-party phone app will receive a wearable device connection event. • In Step 5, the third-party phone app will receive an event that the wearable device is worn. • In Step 6, the third-party phone app will receive an event that the wearable device is not worn. |  |
| The phone sends notifications to the wearable device. | • Your phone app calls the API for sending notifications to the wearable device. • Check that the notification received by your wearable app is consistent with that sent by the phone app. | In step 2, the notification received by the wearable device is consistent with that sent by the phone, including the message content, title, and button. |  |
